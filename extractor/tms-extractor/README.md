# TMS Extractor

เว็บแอปสำหรับดึง **Picking List พร้อมชื่อ Item** จาก Vespa TMS ออกเป็น CSV / Excel / JSON
รันบนเครื่องตัวเอง ล็อคอินด้วย user TMS ของคุณ

## รัน

**วิธีง่ายสุด** — ดับเบิลคลิก `TMS Extractor.bat` (อยู่โฟลเดอร์แม่)

เปิดเบราว์เซอร์ให้อัตโนมัติในโหมดหน้าต่างเดี่ยว **พอปิดหน้าต่างเบราว์เซอร์ server จะปิดตามให้เอง**
ไม่มี process ค้าง และถ้ามีของค้างจากรอบก่อน มันจะเก็บกวาดให้ตอนเปิดใหม่

**วิธีพิมพ์เอง**

```bash
node server.js
```

เปิด `http://localhost:5173`

ไม่มี dependency ไม่ต้อง `npm install` ใช้ Node 18+ (ทดสอบบน v22)

### ถ้าเครื่องยังไม่มี Node.js

`TMS Extractor.bat` จะถามว่าจะติดตั้งให้เลยไหม กด Enter = ตกลง

ติดตั้งผ่าน `winget` ก่อน (ถ้าเครื่องมี) ไม่มีก็ดาวน์โหลด MSI ตัว LTS ล่าสุดจาก `nodejs.org` โดยตรง
มีหน้าต่าง UAC ขออนุญาตหนึ่งครั้ง เสร็จแล้วโปรแกรมรีสตาร์ทตัวเองและเปิดใช้งานได้ทันที

กลไก: `launch.ps1` คืน exit code `10` แปลว่า "ติดตั้งเสร็จ เรียกใหม่" `.bat` วนกลับไปรันซ้ำ
และ `launch.ps1` โหลด `PATH` ใหม่จาก registry ทุกครั้งที่เริ่ม — จำเป็น เพราะ process ที่รันอยู่
ยังถือ `PATH` เดิมของตอนเปิด จะมองไม่เห็น `node` ที่เพิ่งติดตั้ง

เปลี่ยนพอร์ต: `set PORT=8080 && node server.js`

### หมายเหตุเรื่อง launcher

`launch.ps1` เปิดเบราว์เซอร์ด้วย `--user-data-dir` เป็นโฟลเดอร์ชั่วคราว — จำเป็น เพราะถ้าไม่ระบุ
`chrome.exe` จะโยนงานให้หน้าต่างที่เปิดอยู่แล้วจบตัวเองทันที ทำให้รอจังหวะปิดไม่ได้
ผลพลอยได้คือไม่ปนกับ session เบราว์เซอร์ปกติของคุณ และโฟลเดอร์นี้ถูกลบทิ้งตอนปิด

ไฟล์ `.ps1` ต้องเซฟเป็น **UTF-8 with BOM** เท่านั้น ไม่งั้น PowerShell 5.1 อ่านภาษาไทยเป็น ANSI แล้ว parse ไม่ผ่าน

ส่วนขาออกก็ต้องบังคับด้วย บรรทัดแรกของ `launch.ps1` ตั้ง `[Console]::OutputEncoding` เป็น UTF-8
ไม่มีบรรทัดนี้ข้อความไทยจะออกมาเป็นตัวขยะ แม้ `.bat` จะ `chcp 65001` ไว้แล้วก็ตาม

`.bat` เก็บเป็น **ASCII ล้วน** ไม่ใส่ภาษาไทย — ตัว `.bat` ไม่มีทางคุม encoding ของตัวเองได้

## ทำไมต้องมี server

เบราว์เซอร์บล็อก cross-origin request จากไฟล์ local ไป `pdi.vespiario.net` (CORS)
`server.js` ทำหน้าที่แค่ 2 อย่าง: เสิร์ฟไฟล์ static และ forward `/proxy/*` ไป `https://pdi.vespiario.net/tms-api/*`

ไม่ log ไม่เก็บ ไม่เขียนอะไรลงดิสก์ — header `Authorization` ส่งผ่านตรง ๆ

## ความปลอดภัย

- รหัสผ่านถูกส่งไป endpoint `POST /api/tokens` ของ TMS ตัวจริงเท่านั้น แล้วเคลียร์ออกจากฟอร์มทันที
- token เก็บใน `sessionStorage` ของเบราว์เซอร์ ปิดแท็บแล้วหาย ไม่มีการเขียนลงไฟล์
- ทุก endpoint ที่เรียกเป็น **read-only**: `/tokens` (login), `/personal/profile`, `/personal/warehouses`, `/v1/pickinglistheaders/{wh}/search`
- ไม่มีโค้ดส่วนไหนที่ POST/PUT/DELETE ข้อมูลจริงในระบบ TMS

## ใช้งาน

1. ล็อคอินด้วย email/username + password ของ TMS (tenant ปกติคือ `root`)
2. เลือก Warehouse (ดึงจากสิทธิ์ของ user อัตโนมัติ)
3. ตั้ง filter — Status, Area, Keyword, ช่วง Plan Delivery Date
4. กด **ดึงข้อมูล** — มี progress bar และปุ่มหยุดกลางคัน
5. ดูผลได้ 3 มุมมอง แล้วกด export

| ช่อง | ความหมาย |
|---|---|
| Page size | จำนวน PL ต่อ 1 request (500) ถ้า timeout ให้ลดเป็น 200 |
| จำกัดหน้า | ลองดึง n หน้าแรกก่อน ใส่ 0 = ดึงจนหมด |

### แผงตัวกรอง

- ปุ่มซ้ายบนสุด (หรือกด `[`) หุบแผงเหลือแถบไอคอน — ได้พื้นที่ตารางเพิ่ม
- คลิกไอคอนตอนหุบอยู่ = กางออกพร้อมเปิดกลุ่มนั้นให้เลย
- แต่ละกลุ่มพับเก็บได้ คลิกที่หัวข้อ
- ตั้งตัวกรองไว้กี่ช่อง จะขึ้นเป็นตัวเลขข้าง "ตัวกรอง" (ตอนหุบเป็นจุดเขียว) — กันลืมว่าติดฟิลเตอร์ค้างไว้
- จำสถานะหุบ/ขยายไว้ใน localStorage
- จอแคบกว่า 900px แผงกลายเป็น drawer ลอยพร้อมฉากหลังมืด ปิดด้วย Esc หรือคลิกนอกแผง

### ช่วง Plan Delivery

เลือกจากปุ่มลัด: ทั้งหมด / วันนี้ / 7 วัน / 30 วัน / เดือนนี้ / กำหนดเอง
"กำหนดเอง" ถึงจะโผล่ช่องวันที่ให้กรอก — ช่องเต็มความกว้าง อ่านง่ายกว่าวางคู่กัน

ใต้ปุ่มมีสรุปช่วงที่เลือกอยู่เป็น วว/ดด/ปปปป ตลอด กันงงว่าตกลงกรองช่วงไหนอยู่

**ช่วงวันที่กรองฝั่ง client ไม่ได้ส่งไป API** — เพราะ API ไม่มี field รับช่วงวันที่ (ตรวจ bundle
แล้วมีแค่ `planDeliveryDate` เฉย ๆ ไม่มี From/To) ส่งไปก็ถูกเมิน ผลคือ export ออกมาไม่กรอง

วิธีทำงานตอนนี้: ขอข้อมูลเรียง `planDeliveryDate Descending` แล้วคัดทีละหน้าตอนรับมา
พอเจอหน้าที่วันที่เก่ากว่าวันเริ่มต้นที่เลือก ก็หยุดดึงทันที ไม่ต้องไล่จนครบ 14,000 รายการ

Status กับ Area ส่งไป API ด้วย **และ** กรองซ้ำฝั่ง client อีกชั้น — ถ้า API เมินก็ยังได้ผลถูก

แถบสถานะจะบอก `สแกน N · เข้าเงื่อนไข M PL` ให้เห็นว่าคัดจากกี่รายการ

## โหมด Actual Shipment

ปุ่มสลับบนสุดของแผงซ้ายเปลี่ยนไปดึงรายงาน Actual Shipment แทน Picking List

```
POST /v1/reports/actualshipment
{ "planDeliveryDate": ["2026-08-13T00:00:00.000Z","2026-08-13T00:00:00.000Z"],
  "warehouseId": "<guid>" }
```

ต่างจากฝั่ง PL ตรงที่ API คืน array แบนมาให้ตรงรูปแบบรายงานอยู่แล้ว ไม่ต้องแบ่งหน้า
ไม่ต้องแตก `details[]` — 23 คอลัมน์ เรียงลำดับเดียวกับหน้า TMS เป๊ะ

**Trip Date ค่าเริ่มต้น = เมื่อวาน** เพราะข้อมูลของวันปัจจุบันยังไม่ actual
รอบข้อมูลปิดและส่งหลังเที่ยงคืน หน้า TMS ก็ตั้งค่าเริ่มต้นแบบเดียวกัน

endpoint นี้อ้าง warehouse ด้วย **GUID** ไม่ใช่รหัส (ต่างจาก `pickinglistheaders/{code}/search`)
id ติดมากับ `/personal/warehouses` อยู่แล้ว ถ้า build ไหนไม่ส่งมาจะถอยไปถาม `/v1/warehouses/search`

### ชื่อ item ในรายงาน

`reports/actualshipment` ไม่ส่ง item มาให้ มีแต่ `pickingListNo` — ติ๊ก **"ดึงชื่อ item มาด้วย"**
แล้วแอปจะไปดึง `pickinglistheaders/{wh}/search` ซึ่งส่ง `details[]` มาอยู่แล้ว มา join ด้วยเลข PL
จากนั้นแตกเป็น 1 แถว = 1 item แทรกคอลัมน์ `Item No` / `Item Name` / `Item Qty` / `Split Qty` / `ตรวจยอด` ต่อจากคอลัมน์ `Unit`

ไล่หน้าทีเดียวจบ (pageSize 500) แล้วหยุดทันทีที่เจอครบทุกใบ ไม่ยิงทีละ PL —
รายงานวันเดียวมีหลายสิบใบ ยิงทีละใบจะกลายเป็นหลายสิบ request

### ทำไมยอด item ไม่เท่ากับ unit

หาง `-C-04` ในเลข PL แปลว่า PL ใบนั้นถูก**แบ่งส่งหลายเที่ยว** — `unit` ในรายงานคือจำนวนที่ยกไป
เที่ยวนี้ แต่ `details[]` ที่ดึงมาเป็นของทั้งใบ ยอดจึงไม่ตรงกันโดยธรรมชาติ

ยังไม่ได้พิสูจน์กับข้อมูลจริงว่าฟิลด์ไหนคือจำนวนที่ยกไปจริง จึงไม่เลือกแทน — แสดงทั้ง
`Item Qty` (`qty`) และ `Split Qty` (`splitQty`) คู่กัน แล้วเพิ่มคอลัมน์ **ตรวจยอด** บอกว่า
ยอดของ PL ใบนั้นตรงกับ `unit` ด้วยฟิลด์ไหน

| ค่าในคอลัมน์ตรวจยอด | ความหมาย |
|---|---|
| `ตรง (qty)` | ผลรวม `qty` = `unit` — ส่งทั้งใบ |
| `ตรง (split)` | ผลรวม `splitQty` = `unit` — แบ่งส่ง ใช้ `splitQty` เป็นจำนวนจริง |
| `ไม่ตรง (...)` | ไม่ตรงทั้งสองแบบ มีเลขทั้งสามให้ดูในช่อง |

การ์ดสถิติมี `Item Qty รวม`, `Split Qty รวม`, `PL ยอดไม่ตรง` ให้เทียบกับ `Unit รวม`
ถ้าใช้จริงแล้วพบว่าเป็น `ตรง (split)` แทบทั้งหมด ค่อยเปลี่ยนให้เหลือคอลัมน์เดียวได้

เลข PL ในรายงานบางใบมีหางแบบ `-C-04` ต่อท้าย ซึ่งอาจไม่ตรงกับที่เก็บใน PL header
โค้ดจึงลองทั้งแบบเต็มและแบบตัดหางออก ใบที่หา details ไม่เจอยังคงไว้ 1 แถวแต่ช่อง item ว่าง
พร้อมขึ้นเตือนว่ามีกี่ใบ

ไม่มีแถวรวมยอดคั่นแบบรายงาน TMS — ได้ตารางแบนล้วน เอาไปทำ pivot ต่อได้ทันที
ยอดรวมดูได้จากการ์ดสถิติด้านบนแทน

ค่าที่ไม่ได้อยู่ระดับแถวจะเขียนครั้งเดียวแล้วเว้นว่างที่เหลือ — `unit` เป็นค่าระดับ PL,
`actualCost` เป็นค่าระดับ trip ถ้าปล่อยให้ซ้ำ ลาก sum ใน Excel ยอดจะบวมตามจำนวน item/PL

ทำใน `dedupAs()` ที่เดียว หลังเรียง/กรองเสร็จ ทุกทางออก (ตาราง, CSV, Excel, JSON) จึงตรงกัน

## 3 มุมมอง (โหมด Picking List)

**รายการ** — 1 แถว = 1 item. PL ที่มี 3 item แตกเป็น 3 แถว. นี่คือรูปแบบที่เอาไปทำ pivot ต่อได้ดีที่สุด

**สรุปราย PL** — 1 แถว = 1 PL พร้อมจำนวน item, qty รวม, และรายชื่อ item ทั้งหมดในช่องเดียว

**สรุปราย Item** — 1 แถว = 1 item code พร้อม qty รวม, จำนวน PL ที่มี item นั้น, และสัดส่วน % พร้อมแถบเทียบ

ทุกมุมมอง: คลิกหัวคอลัมน์เพื่อ sort, ช่องค้นหากรองทุกคอลัมน์, export ตามมุมมองและคำค้นที่เปิดอยู่

## Export

| ปุ่ม | ได้อะไร |
|---|---|
| CSV | UTF-8 BOM — Excel เปิดอ่านภาษาไทยได้ทันที |
| Excel | `.xlsx` จริง (OOXML) — หัวตารางหนา ตัวเลขเป็น type number จริง |
| JSON | array ของ object เอาไปเข้า script ต่อได้ |

Export ทั้งชุด ไม่ตัดตามหน้าที่แสดงอยู่

เดิมปุ่ม Excel เขียน SpreadsheetML แล้วตั้งนามสกุล `.xls` — เนื้อในเป็น XML แต่นามสกุลเป็น
ไบนารีเก่า Excel เลยเตือน "format and extension don't match" ทุกครั้งที่เปิด

**กับดักที่เจอตอนทำ** — ถ้าไฟล์เปิดแล้ว Excel ขอซ่อมพร้อมข้อความ
`Replaced Part: /xl/worksheets/sheet1.xml part with XML error. Load error. Line 1, column 0`
แปลว่า XML ผิด **ลำดับ element** ไม่ใช่ผิดไวยากรณ์ — XML parse ผ่านหมด zip ก็ไม่เสีย
แต่ `CT_Worksheet` บังคับลำดับตายตัว: `sheetFormatPr → cols → sheetData → autoFilter → mergeCells`
สลับ `autoFilter` กับ `mergeCells` เมื่อไหร่ Excel ทิ้งทั้ง sheet ทันที

อีกตัวคือชื่อคอลัมน์เกิน Z ต้องแปลงเป็น AA/AB ให้ถูก ใช้ `String.fromCharCode(64+n)` ไม่ได้
(รายงาน Actual Shipment พร้อม item มี 28 คอลัมน์)

`public/xlsx.js` เขียน `.xlsx` จริงแทน ไม่มี dependency: ZIP แบบ store (ไม่บีบอัด) + CRC32
+ OOXML ขั้นต่ำ ไฟล์ใหญ่กว่าปกติเล็กน้อยเพราะไม่บีบอัด แลกกับโค้ดที่ตรวจสอบเองได้ทั้งหมด
เวอร์ชัน standalone ใช้ไฟล์เดียวกัน — `build.js` ดึงเข้าไปแทน `__XLSX__` ตอน build

## โครงสร้าง

```
tms-extractor/
  server.js            proxy + static (zero dep)
  public/
    index.html         โครงหน้า
    style.css          ธีม
    xlsx.js            ตัวเขียน .xlsx (zero dep) ใช้ร่วมกับเวอร์ชัน standalone
    app.js             logic: login, fetch, aggregate, render, export
  README.md
```

## แก้ให้ตรงงานตัวเอง

- **เพิ่ม/ลดคอลัมน์** — แก้ `COLS` ใน `app.js` (มี 3 ชุดตามมุมมอง). field ที่มีให้ใช้ดูจากฟังก์ชัน `flatten()`
- **เพิ่ม field จาก API** — เพิ่ม key ใน `flatten()` แล้วค่อยเพิ่มลง `COLS`
- **เปลี่ยน default sort** — แก้ `orderBy` ใน `#run` handler เช่น `['pickingListNo Ascending']`
- **ดึงตาราง Trip แทน** — endpoint คือ `/v1/tripheaders/{wh}/search` body หน้าตาเดียวกัน

## ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ / ทางแก้ |
|---|---|
| เข้าสู่ระบบไม่สำเร็จ 401 | ตรวจ username, password, tenant. API ใช้ field `UserName` + `Password` (ยืนยันจาก validation error ของ server แล้ว) |
| upstream unreachable | ไม่มีเน็ต หรือเข้า `pdi.vespiario.net` ไม่ได้จากเครื่องนี้ (ต้องต่อ VPN บริษัทไหม) |
| session หมดอายุกลางคัน | ออกจากระบบแล้วเข้าใหม่ |
| ดึงช้ามาก | PL มี 14,000+ รายการ ใส่ filter ให้แคบลง หรือใช้ "จำกัดหน้า" ลองก่อน |
| ดึงนานเมื่อเลือกช่วงเก่า ๆ | ช่วงวันที่กรองฝั่ง client ต้องสแกนจากใหม่ไปเก่าจนถึงช่วงที่เลือก ยิ่งย้อนไกลยิ่งสแกนเยอะ |

## หมายเหตุ

ชื่อ item อยู่ใน `details[]` ของ response `pickinglistheaders/{wh}/search` อยู่แล้ว
หน้าเว็บ TMS ตัวจริงไม่ได้ render ส่วนนี้ — แอปนี้แค่เอาข้อมูลที่ API ส่งมาอยู่แล้วมาแสดงและ export
