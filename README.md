# TMS Web — ระบบบริหารจัดการขนส่ง

เว็บแอปสำหรับกองรถของบริษัท ใช้จัดงานขนส่งประจำวันตั้งแต่รับงานจากระบบ TMS ของบริษัท
ไปจนถึงคนขับกดรับงาน ส่งของ และเก็บหลักฐานการส่งมอบจากในรถ

เปิดใช้งานที่ <https://vppwtrs.github.io/tms/>

## ปัญหาที่ระบบนี้แก้

บริษัทมีระบบ TMS อยู่แล้ว แต่ระบบนั้นจบที่ "จ่ายเที่ยวให้ผู้รับจ้างขนส่ง" งานของกองรถตัวเอง
จึงถูกจัดการต่อด้วยกระดาษ ไลน์ และการโทรถามว่า "รถถึงไหนแล้ว"

ระบบนี้รับข้อมูลจาก TMS มาเป็นตัวตั้ง แล้วเติมส่วนที่ขาด: ใครขับเที่ยวไหน คนขับรับงานหรือยัง
ตอนนี้อยู่ที่ไหน ส่งครบหรือยัง และมีหลักฐานอะไรยืนยันบ้าง โดย **ไม่เขียนข้อมูลกลับเข้า TMS**
ของบริษัทเลยแม้แต่ครั้งเดียว — อ่านอย่างเดียวเสมอ

## ใครใช้ ใช้ทำอะไร

**ผู้วางแผนงาน** ดึงเที่ยวของกองรถจาก TMS เลือกพนักงานขับให้แต่ละเที่ยว แล้วสั่งงาน
งานที่สั่งแล้วจะไปรออยู่ในแอปของคนขับ ระบบไม่เดาว่าใครคือคนขับให้ เพราะชื่อใน TMS
พิมพ์อิสระและเดาผิดได้ — คนเป็นผู้ตัดสิน ระบบเป็นผู้จำคำตอบไว้ใช้รอบถัดไป

**พนักงานขับรถ** เปิดจากมือถือ กดรับงาน จัดลำดับว่าจะแวะร้านไหนก่อน ปิดงานทีละจุด
และเก็บหลักฐานการส่งมอบ — ลายเซ็นผู้รับ รูปหลายมุม (สินค้า หน้าร้าน ใบเซ็นรับ) พร้อมพิกัดและเวลา

**ผู้ดูแลระบบ** จัดการบัญชีผู้ใช้ กลุ่มสิทธิ์ ทะเบียนรถ และทะเบียนพนักงานขับ

## ความสามารถ

- **ดึงข้อมูลจาก TMS** — เที่ยวของกองรถ ใบ Picking List รายการสินค้า ค่าขนส่ง และสถานะ
  โดยกรองเฉพาะเที่ยวของกองรถเรา ไม่ดึงงานของผู้รับจ้างรายอื่นเข้ามาปน
- **สั่งงาน** — เลือกคนขับ นำเข้าเป็นเที่ยววิ่งพร้อมจุดส่งและรายการของครบ
- **แอปคนขับ** — หนึ่งงานเต็มจอ ปุ่มขนาดนิ้วโป้ง ปุ่มหลักตรึงล่างจอ ใช้งานได้จริงในรถ
- **หลักฐานการส่งมอบ** — ลายเซ็น รูปหลายมุมพร้อมป้ายบอกว่ารูปไหนคืออะไร พิกัด และเวลา
  หลักฐานที่ยืนยันแล้วแก้ไขไม่ได้
- **ติดตามรถ** — แผนที่แสดงตำแหน่งล่าสุดของทุกเที่ยวที่กำลังวิ่ง เส้นทางย้อนหลัง
  และหมุดทุกจุดที่เก็บหลักฐานไปแล้ว
- **สิทธิ์การใช้งาน** — กำหนดเป็นกลุ่ม (ผู้ดูแลระบบ / วางแผนงาน / ดูอย่างเดียว / พนักงานขับรถ)
  ปรับรายคนได้ และทุกการเปลี่ยนสิทธิ์ถูกบันทึกไว้

## สิ่งที่ระบบนี้ตั้งใจไม่ทำ

- **ไม่เขียนกลับเข้า TMS** ของบริษัท ทุกการเรียกเป็นการอ่าน และรายการ endpoint ที่เรียกได้
  ถูกล็อกไว้ฝั่งเซิร์ฟเวอร์
- **ไม่เดาแทนคน** ในเรื่องที่เดาผิดแล้วมีคนเดือดร้อน — ใครคือคนขับ ใครคือลูกค้า
  ระบบถาม แล้วจำคำตอบ
- **ไม่ตามตำแหน่งนอกเวลางาน** — บันทึกตำแหน่งตั้งแต่คนขับกดรับงานจนปิดเที่ยวเท่านั้น
  และลบอัตโนมัติหลัง 30 วัน หน้าจอของคนขับบอกตลอดว่ากำลังบันทึกอยู่หรือหยุดแล้ว
- **ไม่แสดง 0 แทนคำว่าไม่รู้** — ข้อมูลที่ต้นทางไม่ได้ส่งมาจะเขียนว่าไม่รู้ ไม่ใช่เติมศูนย์
  ซึ่งอ่านได้เป็น "ไม่มีของ"

## เทคโนโลยี

| ส่วน | ใช้อะไร |
|---|---|
| หน้าเว็บ | React + TypeScript + Vite (PWA) |
| ฐานข้อมูล / สิทธิ์ | Supabase (PostgreSQL + Row Level Security + Auth) |
| ตรรกะฝั่งเซิร์ฟเวอร์ | PostgreSQL functions + Supabase Edge Functions (Deno) |
| แผนที่ | Leaflet + OpenStreetMap |
| Deploy | GitHub Actions ขึ้น GitHub Pages |

กฎการเข้าถึงข้อมูลทั้งหมดอยู่ในฐานข้อมูล ไม่ใช่ในหน้าจอ — คนขับเห็นเฉพาะงานของตัวเอง
เพราะ Row Level Security บังคับไว้ ไม่ใช่เพราะหน้าจอไม่แสดง

## โครงสร้างโปรเจกต์

```
web/                  หน้าเว็บ (React + Vite)
  src/pages/          หน้าจอแต่ละหน้า
  src/api/            ชั้นคุยกับ Supabase และ TMS
  src/components/     ส่วนประกอบที่ใช้ซ้ำ รวมหน้าจอฝั่งคนขับ
supabase/
  migrations/         ประวัติการเปลี่ยนโครงสร้างฐานข้อมูล
  functions/          Edge Functions (ประตูออกไป TMS และงานที่ต้องใช้สิทธิ์ระดับระบบ)
server/               ระบบเดิมบน LAN — ยังอยู่ในโค้ด แต่ไม่ได้ใช้บนคลาวด์
```

## การพัฒนา

ต้องมี Node.js 20 ขึ้นไป

```bash
cd web
npm install
npm run dev          # โหมดพัฒนา (ต่อ Supabase ตาม .env)
npm run build:cloud  # build ตัวที่ขึ้น GitHub Pages
npx tsc --noEmit     # ตรวจชนิดข้อมูล
npx vitest run       # รันเทส
```

ตั้งค่าใน `web/.env`

```
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

ฝั่งฐานข้อมูล

```bash
npx supabase db push --linked                  # ส่ง migration ขึ้นฐาน
npx supabase functions deploy <ชื่อฟังก์ชัน>     # ส่ง Edge Function
```

การ deploy หน้าเว็บทำอัตโนมัติเมื่อ push ขึ้น `main`
