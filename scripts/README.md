# สำเนาหลักฐานการส่งมอบขึ้น Google Drive

ลายเซ็นและรูปหน้างานคือของชิ้นเดียวที่ตอบลูกค้าได้เวลามีข้อโต้แย้ง และเป็นของที่
โตเร็วที่สุดในระบบ — โควตาไฟล์ของแพลนฟรีคือ 1 GB ที่ประมาณ 1.2 MB ต่อจุดส่ง
ก็เต็มราว ๆ 850 จุด สำเนาจึงต้องมีก่อนที่จะถึงวันที่ต้องลบอะไรทิ้ง

## ทำไมไม่ยิงเข้า Google Drive API ตรง ๆ

service account ของ Google **ไม่มีโควตา Drive ของตัวเอง** ไฟล์ที่มันสร้างใน
โฟลเดอร์ที่คนแชร์ให้จึงอัปไม่ขึ้น ทางที่ใช้ได้จริงมีสองทาง คือ Shared Drive
(มีเฉพาะ Google Workspace) หรือ OAuth refresh token ของคนจริง ซึ่งถูกเพิกถอน
แล้วเงียบไปได้ตลอดโดยไม่มีใครรู้จนถึงวันที่ต้องใช้ของ

สคริปต์นี้เขียนลงโฟลเดอร์ธรรมดา แล้วปล่อยให้แอป Google Drive ในเครื่อง sync เอง
ของที่ต้องดูแลน้อยกว่ามาก และเวลาพังมันพังแบบที่คนเห็น — ไฟล์ไม่ขึ้นในโฟลเดอร์

## ตั้งครั้งเดียว

1. ติดตั้ง **Google Drive for Desktop** แล้วล็อกอินบัญชีที่จะเก็บของ
2. สร้างโฟลเดอร์ใน Drive เช่น `TMS-POD` จำ path ในเครื่องไว้ (เช่น `G:\My Drive\TMS-POD`)
3. คัดลอกไฟล์ตั้งค่า แล้วใส่ค่าให้ครบสามตัว

   ```
   copy scripts\backup.env.example scripts\backup.env
   ```

   `SUPABASE_SERVICE_ROLE_KEY` อยู่ที่ Supabase dashboard > Project Settings > API
   **คีย์ตัวนี้ข้าม RLS ทั้งหมด** อยู่ในเครื่องเท่านั้น ห้าม commit ห้ามส่งต่อ

4. ลองรันมือหนึ่งรอบ

   ```
   node scripts/backup-pod-photos.mjs
   ```

## ตั้งให้รันเองทุกคืน

Task Scheduler > Create Basic Task

| ช่อง | ค่า |
|---|---|
| Trigger | Daily เวลา 01:00 |
| Action | Start a program |
| Program | `node` |
| Arguments | `scripts\backup-pod-photos.mjs` |
| Start in | `D:\TMS Project` |

ติ๊ก **Run whether user is logged on or not** ไว้ด้วย ไม่งั้นงานจะไม่รันตอนไม่มีคนล็อกอิน

## สิ่งที่ได้

```
TMS-POD/
  2026-08/
    1279/
      signature.png      ลายเซ็นผู้รับ
      goods-1.jpg        รูปสินค้าที่ส่ง
      shopfront-1.jpg    รูปหน้าร้าน
      document-1.jpg     รูปใบเซ็นรับ
      info.json          ใครรับ เมื่อไหร่ พิกัด ใบไหน เที่ยวไหน
```

แยกตามเดือนเพราะเวลาลูกค้าทักมา คนจะเปิดหาจาก "เดือนที่แล้ว" ไม่ใช่จากเลขออเดอร์
ที่ไม่มีใครจำได้

`info.json` สำคัญพอ ๆ กับรูป — โฟลเดอร์ที่มีแต่ไฟล์ภาพตอบข้อโต้แย้งไม่ได้ และคนที่
เปิดมันในอีกสามปีอาจไม่มีสิทธิ์เข้าฐานแล้ว หรือฐานอาจไม่มีแถวนั้นแล้ว

## ข้อจำกัดที่ตั้งใจให้เป็นแบบนี้

- **เขียนอย่างเดียว ไม่ลบอะไรทั้งสิ้น** ทั้งในถังและในเครื่อง
  การลบรูปเก่าเป็นการตัดสินใจคนละอันกับการสำรอง และยังไม่มีอะไรบังคับให้ต้องลบตอนนี้
- รันซ้ำได้ ข้ามไฟล์ที่มีอยู่แล้ว ตั้งรันทุกคืนได้โดยไม่โหลดของเดิมซ้ำ
- รูปไหนโหลดไม่สำเร็จจะถูกข้ามและจดไว้ รอบหน้าลองใหม่ให้เอง แล้วสคริปต์จบด้วย
  รหัสไม่ปกติเพื่อให้ Task Scheduler ขึ้นสถานะล้มเหลว — งานสำรองที่ล้มเงียบ ๆ
  คือสิ่งที่คนไปรู้ตอนต้องใช้ของ ซึ่งสายเกินไปแล้ว
