# แผนออกแบบใหม่: หน้าพนักงานขับรถ

ขอบเขต: `web/src/pages/MyJobs.tsx` และสไตล์ `.job-*` เท่านั้น
**ธีมเดิมทั้งหมด** — ใช้ token ที่มีอยู่ใน `tokens.css` ไม่เพิ่มสีใหม่แม้แต่สีเดียว
สิ่งที่เปลี่ยนคือ *ลำดับความสำคัญของข้อมูล* และ *ตำแหน่งของปุ่ม* ไม่ใช่หน้าตาของแบรนด์

## สิ่งที่แอปส่งของจริงทำเหมือนกันหมด

ดูจากรูปแบบที่ใช้ตรงกันใน Grab Driver, Lalamove Driver, Flash Express, Kerry,
Amazon Flex, Onfleet, Samsara Driver — แม้แต่ละเจ้าจะต่างกันที่รายละเอียด แต่ 8 ข้อนี้ตรงกัน:

| หลักการ | ของเราตอนนี้ |
|---|---|
| **1 งานเต็มจอ** — โชว์งานที่กำลังทำอันเดียว งานอื่นซ่อนไว้ใต้แท็บ | ❌ list ทุกเที่ยวเรียงลงมา ต้องเลื่อนหา |
| **ปุ่มหลักตรึงล่างจอ** — อยู่ในระยะนิ้วโป้งเสมอ ไม่ต้องเลื่อนหา | ❌ ปุ่มอยู่ท้ายการ์ด เลื่อนหนีขึ้นไปได้ |
| **จุดส่งถัดไปเด่นที่สุด** — จุดที่เหลือย่อเป็นบรรทัดเดียว | ❌ ทุกจุดหน้าตาเท่ากัน |
| **ปุ่มนำทางเป็นปุ่มใหญ่** — คนขับกดตอนสวมถุงมือ/รถสั่น | ❌ ปุ่ม `sm` สูง 40px |
| **แถบความคืบหน้าของงาน** — รับของ → ออกรถ → ถึงจุด → ส่งเสร็จ | ❌ มีแค่ badge สถานะ |
| **ยืนยันงานสำคัญด้วยการปัด** (slide to confirm) กันกดพลาดตอนรถสั่น | ❌ ปุ่มกดธรรมดา |
| **ตัวอักษรใหญ่ คอนทราสต์สูง** — อ่านกลางแดดผ่านกระจกรถ | ⚠️ ใช้ scale เดียวกับหน้าออฟฟิศ |
| **บอกสถานะการส่งข้อมูล** — "รอส่ง 2 รายการ" เมื่อสัญญาณหลุด | ❌ ยังไม่มี |

## เฟส A — โครงหน้าใหม่ (แกนหลัก) ✅ ทำแล้ว

ไฟล์ที่เกิดขึ้นจริง:
- `web/src/components/driver/JobFocus.tsx` — งานที่กำลังทำ หนึ่งเที่ยวเต็มจอ
- `web/src/components/driver/JobProgress.tsx` — แถบ 4 ขั้น อ่านจากข้อมูลจริงล้วน
- `web/src/components/driver/StopCard.tsx` — `NextStop` (จุดถัดไป) + `StopRow` (จุดอื่น ย่อ)
- `web/src/pages/MyJobs.tsx` — เหลือหน้าที่เลือกงาน + `PodSheet`
- `web/src/a11y/myjobs.a11y.test.tsx` — 3 เคส

บทเรียนจากการทำจริง:
- แถบขั้นตอนเวอร์ชันแรกนับ "ส่งของ" ว่าเสร็จตั้งแต่ส่งได้จุดเดียว ทำให้แถบขึ้นเขียว
  ทั้งที่ยังเหลืออีกหลายจุด — ต้องนับครบทุกจุดเท่านั้น
- เพิ่มไฟล์เทสใหม่แล้ว `dashboard.a11y` ล้มแบบ flaky (รันเดี่ยวผ่าน รันทั้งชุดล้ม)
  สาเหตุคือ `asyncUtilTimeout` ของ testing-library ที่ default 1 วินาที ไม่พอเมื่อหลายไฟล์รันขนาน
  แก้ที่ `web/src/test/setup.ts` เป็น 5 วินาที

### แผนเดิมของเฟสนี้

เปลี่ยนจาก "รายการเที่ยววิ่ง" เป็น "งานที่กำลังทำ"

```
┌──────────────────────────┐
│ TRP-2026-0059   กำลังส่ง │  ← หัวเรื่องตรึงบน
│ ●━━━━●━━━━○━━━━○         │  ← แถบขั้นตอน
├──────────────────────────┤
│ จุดถัดไป  2 จาก 3        │
│ นครราชสีมา               │  ← ใหญ่ที่สุดในจอ
│ บริษัท ไทยฟู้ดส์         │
│ นัดหมาย 15:03            │
│ ┌──────────┬───────────┐ │
│ │ 📞 โทร   │ 📍 นำทาง  │ │  ← สองปุ่มใหญ่เท่ากัน
│ └──────────┴───────────┘ │
├──────────────────────────┤
│ จุดอื่นในเที่ยวนี้ (ย่อ) │
│ ✓ ขอนแก่น — ส่งแล้ว      │
│ ○ ระยอง — รอส่ง          │
└──────────────────────────┘
│ ▸▸ ปัดเพื่อยืนยันส่งเสร็จ │  ← ตรึงล่างจอ
└──────────────────────────┘
```

ขั้นตอนทำ:

1. แยก `MyJobs.tsx` เป็น `pages/MyJobs.tsx` (ตัวเลือกงาน) + `components/driver/JobFocus.tsx` (งานปัจจุบัน) + `components/driver/StopCard.tsx`
2. เพิ่ม state `activeJobId` — ค่าเริ่มต้นคือเที่ยวที่ `in_progress` ใบแรก ถ้าไม่มีค่อยเป็นใบที่ใกล้ที่สุด
3. งานอื่นย้ายไปอยู่หลังปุ่ม "เที่ยวอื่น (3)" ที่เปิดเป็น sheet
4. `.job-cta` เปลี่ยนเป็น `position: sticky; bottom: 0` + `padding-bottom: env(safe-area-inset-bottom)` (iPhone มีแถบ home ทับ)
5. ปุ่มโทร/นำทางขยายเป็น `size="lg"` เต็มความกว้างครึ่งจอ สูง ≥ 56px

ไม่แตะ API เลย ข้อมูลที่ต้องใช้ `GET /my-jobs` ส่งมาครบอยู่แล้ว

## เฟส B — ฟอร์ม POD เป็นขั้นตอน

ตอนนี้เป็นฟอร์มเดียวยาว: ชื่อ + ลายเซ็น + รูป + หมายเหตุ ล้นจอตั้งแต่ยังไม่ใส่รูป
(เห็นชัดในภาพพรีวิว — ปุ่มบันทึกเกือบชนขอบล่าง)

แอปจริงแตกเป็นสเต็ปละอย่าง เพราะคนขับทำทีละอย่างอยู่แล้ว และแต่ละสเต็ปเต็มจอ = กดง่าย:

```
1/3 ถ่ายรูปหน้างาน      [ข้าม]
2/3 ให้ผู้รับเซ็น
3/3 ตรวจแล้วยืนยัน      ← สรุปให้ดูก่อนส่ง
```

- ใช้ `Modal` ตัวเดิม เปลี่ยนแค่เนื้อในตาม step
- ปุ่ม "ถัดไป" ตรึงล่าง แตะได้ด้วยนิ้วโป้ง
- ลายเซ็นได้พื้นที่เต็มจอจริง (ตอนนี้สูงแค่ ~180px)
- สเต็ป 3 โชว์รูป + ลายเซ็น + ชื่อผู้รับ ให้ตรวจก่อนกดส่ง — แก้ย้อนได้ ต่างจากตอนนี้ที่ส่งแล้วล็อกทันที

## เฟส C — อ่านง่ายในรถ

ไม่เปลี่ยนสี เปลี่ยนแค่ขนาดและน้ำหนัก เฉพาะใน scope หน้าคนขับ:

- ประกาศ `.driver-scope { --font-base: 17px; --font-lg: 22px; --font-xl: 30px }` ครอบเฉพาะหน้านี้
- ปุ่มทุกตัวในหน้านี้ `min-height: 56px` (มาตรฐาน Apple คือ 44px แต่นั่นคือตอนนั่งนิ่ง)
- ชื่อปลายทางใช้ `--font-xl` + `font-weight: 700`
- ธีมมืดมีอยู่แล้วใน `tokens.css` (บรรทัด 298+) — เพิ่มแค่ปุ่มสลับที่กดถึงง่ายในหน้านี้ สำหรับขับกลางคืน

## เฟส D — รายละเอียดที่ทำให้รู้สึกเหมือนแอปจริง

- **ปัดเพื่อยืนยัน** เฉพาะปุ่มที่ย้อนไม่ได้ (ปิดงาน / ส่งเสร็จ) — ปุ่มอื่นกดธรรมดา
- **สั่นตอบรับ** `navigator.vibrate(30)` เมื่อยืนยันสำเร็จ (Android; iOS ไม่รองรับ ปล่อยเงียบ)
- **แถบสถานะการส่ง** "รอส่ง 2 รายการ" — ผูกกับคิว offline ของ [PLAN-driver-photo.md](PLAN-driver-photo.md) เฟส 4
- **ดึงลงเพื่อรีเฟรช** แทนปุ่มโหลดใหม่

## ลำดับและแรงที่ใช้

| เฟส | ได้อะไร | แรง |
|---|---|---|
| A | คนขับเห็นสิ่งที่ต้องทำต่อทันทีโดยไม่ต้องเลื่อน | 1–1.5 วัน |
| B | เก็บ POD จบได้โดยไม่ต้องเลื่อนจอกลางงาน | 1 วัน |
| C | อ่านออกกลางแดด กดไม่พลาด | 0.5 วัน |
| D | ความรู้สึกเทียบเท่าแอปเชิงพาณิชย์ | 1 วัน |

ทำ A ก่อนตัวเดียวแล้วให้คนขับลองจริง 1 สัปดาห์ — A เปลี่ยนวิธีใช้งานมากที่สุด
ถ้าคนขับยังหางานไม่เจอหลังทำ A แล้ว เฟสอื่นก็แก้ไม่ตรงจุด

## กติกาที่ต้องรักษาระหว่างทำ

- ห้ามเพิ่มสีนอก `tokens.css` — ถ้ารู้สึกว่าต้องใช้สีใหม่ แปลว่าลำดับความสำคัญยังผิด
- ห้ามให้ตัวเลขเงินโผล่ในหน้านี้ (server ไม่ส่งมาให้ตั้งแต่ต้น — อย่าไปดึงเพิ่ม)
- ทุกหน้าจอใหม่ต้องมีเทส a11y คู่ใน `web/src/a11y/` ตามกติกาโปรเจ็ค
- ปุ่มหลักต้องแตะได้ด้วยนิ้วโป้งขวาบนจอ 6.1 นิ้วโดยไม่ขยับมือ — เกณฑ์ตรวจรับของทุกเฟส
